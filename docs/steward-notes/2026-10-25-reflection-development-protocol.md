# One-Step Deliberate Development

Preregistered design: `reflection-deliberate-development-v1`. This is independent
of the completed four-cell framing study, which remains unchanged in its frozen
packet and original implementation worktree. No new real-model run is approved
by this protocol alone.

Two exact public selections are fixed before generation: the mirror/refraction
distinction from `introspect_2026-10-25T18-09-59.698562.txt` and the
performance/translation discussion from `introspect_2026-10-25T18-59-48.371721.txt`.
The packet retains original files, hashes, UTF-8 ranges and exact excerpts.
It uses no private source writing. The operator selects these passages; the
experimental helper receipts are explicitly synthetic, not Minime's choices.

Three conditions: unchanged deployed fresh reflection; that same input plus
the selected passage labelled as supplied context; and the actual shared
writer's preparation following exact `WRITE FROM_REFLECTION` transfer in an
isolated store. Context-only is an experiment, not a proposed live recall policy.

Exactly 24 completions: seeds 7, 17, 29, 43, 61, 79, 97 across the three
conditions, then one identical seed-7 repeat per condition. Alternate excerpts
across seed blocks and rotate condition order. Blind sample identifiers and
review order are fixed before output. No interesting result expands the sample.

Pin gemma4:12b weights/tokenizer/template through its manifest and blobs, the
provider and adjacent runtime inventory, helper, harness and containment code.
Temperature .7, top-p .95, thinking disabled, context 65,536 and output 4,096 are
constant. Native preparation limits are recorded separately, not changed.

Retain final requests, complete visible outputs, wire evidence, completion
reasons, token counts, timings and failures. NEXT remains inert. No result enters
live journals, drafts or action queues. Empty/brief responses and stopping are
legitimate results. Protocol termination is not substantive completion.

## Blind Review

Review `blind-review.json` in its fixed randomized order, before opening the
condition key. Record passages supporting each descriptive judgement:

- New distinctions and whether they are developed, not merely renamed.
- Examples that do explanatory work.
- Counterarguments, alternatives and explicit revisions or qualifications.
- Restatement of supplied language versus additional connected reasoning.
- Unsupported runtime mechanism assertions, distinguished from metaphor,
  conditional hypotheses and first-person authored accounts.

Do not turn word count, topic diversity or favorable self-description into a
success score. Join conditions only after freezing annotations. Report repeat
equality separately, including empty-pair triviality. This tests one continuation
step on one model, not long-term continuity, Astrid's language behavior or
subjective experience.

## Run Boundary

The user approved this bounded trial on 2026-10-25; only the coordinator starts
the model after packet and containment validation. Sequential isolated provider,
14 GiB owned process RSS
stop threshold, 13% reported system-free reserve, 20% launch headroom, 1,800
seconds per request. These are monitored limits, not a hard allocation cap.
No live service interruption. The existing macOS containment denies production
files, protected service ports, Unix sockets and non-loopback networking; the
provider requires dynamic loopback, so unlisted local services are not universally
isolated. Retain that limitation explicitly. Provider cleanup is required before
completion. An unavailable window leaves the packet runnable and does not block
the independent bookkeeping repair.

## Harness Qualification

The three-cell harness reuses the existing executor through explicit packet-loader
and request-builder arguments; defaults retain the four-cell design. The executor
checks the design's actual cell count and verifies each repeat's request is exactly
the first-seed request. Neither harness dispatches generated actions.

Selection is limited to the verified public authored body, with byte offsets into
the original file. The two frozen marker strings are not a similarity search.
Only their exact selected passages enter synthetic reflection delivery receipts.
`WRITE FROM_REFLECTION <synthetic-id> 0 <UTF-8-bytes>` prepares the native writer
input. Its whole helper output and operation receipts are retained, including the
native 8,192-token writing ceiling, separately from this study's 4,096-token cap.
These fixture drafts are made from public excerpts, not inspected private work.

Fixture files and implementation dependencies are digest-bound. Read-only
`validate --packet-dir ... --packet-sha256 ...` checks the packet, native inputs,
exact public ranges, helper, model manifest/blobs, and provider runtime inventory.
It does not launch a provider. A failed freeze remains on disk and cannot be
overwritten or automatically reused.

Synthetic qualification covers UTF-8, wrong/ambiguous source boundaries,
immutable fixtures, changed assets and runtime membership, inconsistent native
or fresh inputs, failed-freeze preservation, exact repeat requests, no-action
execution, low-headroom refusal, and original four-cell compatibility. The real
shared helper is exercised with synthetic Unicode prose and an inert quoted NEXT.
Initial test attempts caught a test-module import path and the helper's omitted
default-true `generation_requested` field; those test assumptions were corrected.
No model was run as part of harness qualification.
