## Reproduced Adapter Finding

One separate boundary defect is reproduced: direct re-entry into
`_run_shared_source_study` with the same accepted action identity and identical
wire evidence makes a second provider call and writes a second timestamped public
file. The shared helper correctly returns the original delivery acknowledgement;
that does not deduplicate the adapter's publication. Two files, one immutable
navigation receipt, and unchanged response bytes are observed in synthetic state.

Before the approved repair, `test_reentering_same_action_must_not_publish_twice`
was a strict expected failure. Running it with `--runxfail` failed at
`assert len(entries) == 1`, with two entries. This unsuccessful attempt is retained
as the reproduction, not relabelled a passing qualification. It does not show
that the normal scheduler re-entered a live job, and it does not explain the
mid-response splice. After the guard below, the same test passes without xfail.

Other real-adapter/helper checks establish:

- A stubbed splice, including Unicode and quoted commands, is preserved exactly.
- A failed transport attempt followed by success produces one accepted response
  and one publication, without concatenation.
- Duplicate helper acknowledgements are idempotent; conflicting evidence cannot
  replace the accepted receipt or publish the conflicting response.
- A late completion for a displaced offer is rejected without replacing the
  newer delivery, publication or selected NEXT.
- A publication-file failure leaves the accepted receipt and NEXT intact, with
  no claimed authored file. Failure after file creation but during journal-record
  persistence leaves that one file intact. Neither failure triggers regeneration.

The synthetic splice is held in the test fixture, not copied from private writing.
No actual provider, network endpoint or live state is used by the tests.

## Reflection-Only Publication Repair

Runtime changes are confined to the new
`minime_autonomy/reflection_publication.py`, its import in `runtime.py`, and the
`_run_shared_source_study` body. Non-reflection reading and private-writing routes
retain their publication behavior. Neither the cleanup methods nor the frozen
audit script changed. The comparison packet's audit-script hash remains valid.

Before provider submission, a reflection reserves its durable action/input
identity under the existing pinned `mailbox_fs.Directory` filesystem discipline.
Content-free receipts live in `runtime/reflection_publications`, separate from
authored history. Their versioned envelope binds owner, action, input, operation
nonce, phase, native delivery hashes and public publication hash/filename. Unknown
schemas, corrupt receipts, conflicting bindings, symlink paths or changed files
fail visibly without overwriting them. This is integrity detection, not a signed
defence against an operator who can deliberately rewrite all evidence.

The owner-scoped file lock covers only bounded filesystem transitions; it is
never held across inference. Native delivery must already exist and match its
input/request/response identities before publication. A publishing receipt is
durable before the public file is atomically linked without overwrite. The final
receipt follows publication and existing artifact/journal side effects. A
completed retry verifies the retained native evidence and publication, then
returns metadata without a provider call, second publication or repeated NEXT
side effects. A new explicit action with a fresh input still generates normally.
The real helper gives independent `INTROSPECT` preparations distinct navigation
IDs even when their prompt text is identical after normalizing the ID-bearing
exact-transfer command. Both are generated and published in the regression;
repeated interests and identical framing are not input-identity collisions.

Returned failure and uncertain execution are intentionally different:

- After a synchronous provider invocation returns no usable response, and no
  native delivery evidence exists, the original owner records `failed_unaccepted`.
  Re-entering that same action cannot replay it. A deliberately new action may
  acquire the exact still-pending input after rechecking native evidence under
  the same lock. No failed transport is silently retried by this mechanism.
- A crash without that durable acknowledgement remains `reserved` and uncertain.
  Accepted, publishing or published-but-incomplete work also requires explicit
  reconciliation. A new action cannot bypass these states for the same input.
- Native evidence appearing after an unaccepted-failure receipt prevents a new
  invocation. Existing legacy delivery without a guard is not adopted or replayed.
  A failure in the receipt write itself does not manufacture a safe retry.

The actual-adapter regression reuses the exact synthetic pending native offer
under an explicitly new host action after a returned connection failure. It
verifies one subsequent accepted receipt/publication, no old-action replay, and
no regeneration after acceptance. Separate real-adapter tests preserve accepted
NEXT across file/publication failures and crash recovery; quoted examples and
malformed prose are not rewritten or rejected for their content.

Remaining recovery debt is deliberate and visible: interrupted receipt writes,
pre-provider host-admission failure after reservation, or publication/database
mirror failure may require operator reconciliation. There is no automatic
recovery command, TTL release, database-side-effect replay, or inference that
missing publication means generation never occurred. Existing accepted response
artifacts and public files survive these failures. This repair does not establish
provider-side cancellation or exactly-once remote execution after disconnection.
Concurrent cooperative invocations are covered; independently modifying native
reader state outside the runtime's invocation discipline is not authorized by
these receipts.

Old accepted preparations with retained native delivery artifacts are refused
before generation; the guard does not reconstruct historical publication success
or automatically adopt old receipts. It reads only the input's native delivery
directory, not another private history or a speculative historical reconstruction.
Legacy history whose acceptance artifacts were externally removed or replaced
is outside this absence check's assurance and needs reconciliation, not a claim
of verified unaccepted execution. New guarded operations additionally bind their
recorded delivery hashes and refuse missing/tampered accepted artifacts.

No authored-state migration is introduced. Rollback is **not** automatically safe
just because old readers can decode the authored store: an older agent does not
enforce these new host receipts. Preserve the receipt directory and native/public
evidence, drain accepted work, and reconcile pending/interrupted operations before
considering an older runtime. Never delete the guard or restore older state over
newer accepted output to make a replay possible. The current guard refuses unknown
receipt schema versions; this does not imply that an older binary does so.

## Reproduction

Initial focused audit coverage: 24 passed, one strict expected failure. The combined
audit, private-writing continuation, source-study diagnostics and shared-reader
run completed with 86 passed and the same one expected failure in 24.17 seconds.
The explicit `--runxfail` reproduction failed as expected with two publications
instead of one. Re-auditing the checked-in frozen evidence completed successfully
with zero cleanup/publication mismatches and no pinned-source drift.

After the guard, the combined publication, audit, reflection-frame, private
continuation, diagnostics and shared-reader suites passed 118 tests with one
existing skip in 28.61 seconds. The skip requires an older immutable helper and
does not represent a tested downgrade path. A preceding combined attempt had
109 passed, one skipped and one cross-process test failure: a spawned worker
timed out, with a missing-lock-file error later observed. The isolated rerun
passed; the cause of that attempt is not established. The concurrency fixture
now launches minimal production-guard subprocesses behind an explicit stdin
barrier rather than importing the full test/runtime fixture module in each
spawned worker. Same-action and competing-action cases, including returned-failure
handoff, are covered without changing the production lock helper.
The final explicit real-helper fresh-identity assertion plus all four contention
cases passed again (five tests, 1.81 seconds) after this run. Runtime code was
unchanged between these checks.
